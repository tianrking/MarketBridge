# 10 · 怎样加入新市场、策略与研究业务

## 新市场不是只加 ticker

先定义 Instrument 的资产类别、产品、单位、合约乘数、到期、发行方、链与地址、结算条件。
区分 same_asset / convertible / hedge / correlated；登记来源和 known_at_ms。
加数据源前检查原生接口能力、成本、限额和授权，再实现专用连接器；遇到缺字段应保留缺失。
路径可参考 src/connectors、src/core/instrument.rs 与 docs/architecture.md。

## 添加策略模型

新模型使用独立 versioned name，例如 `custom-basis/v1`，在 research_lab::evaluate 注册。
输入必须包含当时可知的数据与假设；输出要有状态、原因、单位、已知与未知成本。
不用同一套套利公式混算商品期货、股票 ETF、黄金 token 和跨链包装资产。

最小验收包括：正常样本、单位不一致、过期/倒序时间、缺失费用、极端数值、部分成交、
库存不足、重复证据/ID、输出可复现与错误归档。更新系统模型列表、SDK 示例、工作台选项
及本目录文档。先提供 reference-only 模型是有效交付，但不能叫已验证套利策略。

## 研究迭代怎么组织

定义一个可证伪问题，例如“观察到的跨平台价差在计入真实手续费后是否持续存在” →
保存样本和数据质量 → 冻结成本/资产关系版本 → 按时间拆分样本 → 比较延迟与成本敏感性 →
进行库存和退出场景模拟 → 归档成功与失败 → 再决定是否值得另建执行系统。

可以输出的研究产品包括带证据的观察报告、数据质量评估、条件扫描订阅以及可复现实验服务。
这不是对收入的保证：收费前必须解决数据许可、服务稳定性、客户使用边界和资产覆盖声明。
不要将 `conditional_net_quote` 直接包装成“可赚金额”，也不要出售未核实授权的上游行情。

## 当前明确不做的事情

下单、签名、私钥管理、代客交易、自动借贷、跨链资产移动、保证兑换、真实账户收益核对。
若将来另建执行系统，应是独立授权、独立风控与账本的工程，不通过工作区请求偷偷加入。
